# 独立归档导出与导入

2026-11-17 实现 FR-13：在“备份版本”页把任一完整版本导出为一个 `.bsar` 文件，选择归档导入当前备份目标，生成新的完整版本，再使用原有“还原到…”流程恢复。导入不需要原来源目录或原仓库；导出读取已提交版本，来源文件删除后仍可导出。

## 使用方法

1. 选择备份目标，在版本列表中点击某一行的下载图标“导出归档”，选择一个新的文件名。已有文件会被拒绝覆盖。
2. 将归档复制到其他位置。原仓库可以停止或移走。
3. 启动并选择一个可写的备份目标，点击列表上方“导入归档”，选择文件。
4. 等待“归档已导入为新版本”，在版本列表选择新版本，点击“还原到…”，选择新建或空目录。

取消文件选择不创建执行记录。导出/导入有独立进度和持久化记录，展示归档路径；文件已存在、格式不支持、损坏及空间不足有明确反馈。导入版本保留原任务标识、来源、选择范围、筛选规则和元数据，使用新的版本 ID，并在 `imported_from` 记录原版本及格式；目标压缩策略决定新版本的编码。

## 课件的采用与调整

参考 [《打包解包技术》实验指导.pdf](../ref/《打包解包技术》实验指导.pdf)，第 2—4 页采用“遍历/筛选与打包分工、公共头、文件头与数据顺序排列”的结构；第 10—13 页采用父目录先于子项、空目标恢复、硬链接关系及目录属性最后恢复的原则。

| 课件思路 | 项目实现 |
| --- | --- |
| 公共头、头记录、数据块 | BSAR1 文件头、带类型/长度的记录、内容记录和最终摘要 |
| 固定 200 字节路径及扩展头 | 使用有界 UTF-8 JSON 保存路径/属性，保持项目原有路径校验，避免扩展头混淆与路径截断 |
| 本机 `sizeof(mode_t/time_t/off_t)` 的二进制字段 | 容器整数使用固定宽度大端序；清单沿用十进制字符串保存 64 位长度和时间，避免 ABI 结构体布局依赖 |
| 512 字节补齐数据块 | 数据记录最多 256 KiB，精确长度，无尾部补零；沿用现有传输缓冲与 Huffman/LZ77 独立编码块 |
| CRC64 | 记录全包 SHA-256，并核对清单、警告、存储内容、解压内容的既有摘要 |
| `chdir()` 切换相对路径 | 通过固定目录 fd 和不跟随链接的打开方式处理，避免修改 Qt 多线程进程的全局工作目录 |
| 解包时创建文件 | 先在仓库导入成已验证版本，再复用受检还原流程，保留硬链接、FIFO、设备节点及元数据行为 |

## BSAR1 格式

容器由项目 C++ 自行读写，未调用 tar/zip 打包库。

```text
文件头："BSAR" + u16(version=1) + u16(flags=0)
记录头：u32(type) + u64(payload_length)，均为大端序

Summary   完整版本摘要 JSON，唯一且必须在最前
Warning*  版本警告 JSON，必须先于文件条目
Entry*    清单条目 JSON，保留路径、类型、元数据、编码和摘要
  Data*   仅普通文件紧随其 Entry；保存版本中实际编码的内容块
  FileEnd 普通文件结束，空文件同样必须具备；长度为 0
Final     u64(此前记录数) + u64(此前字节数) + 32 字节 SHA-256
EOF       不允许多余尾字节
```

JSON 记录小于 64 KiB，数据记录为 1—256 KiB，FileEnd 为零长度，Final 固定 48 字节。先核对类型和声明长度再分配缓冲。最终摘要覆盖文件头和全部非 Final 记录的头/负载；最终计数和长度另行核对。SHA-256 用于完整性检查，不是身份认证。

目录、软链接、硬链接、FIFO、字符/块设备及历史 socket 只占清单记录；内容仅为普通文件代表项存一份。软链接目标保留原始字节，硬链接使用已验证的相对代表路径。目录根属性放在版本摘要中。旧格式 1—3 缺失的属性继续按历史兼容规则处理，不伪造元数据。

## 导出、导入及失败边界

导出通过现有版本/清单/警告/内容接口读取，连接持有版本读引用以阻止同时删除。在目标目录的私有临时文件中顺序写入归档，完整读回验证清单、范围、内容和最终摘要，刷新并同步后无覆盖发布。目标不能位于来源、仓库或 Agent 状态目录内。

导入把已固定的普通文件复制为私有快照，检查复制前后文件身份、长度和修改状态；快照打开后立即解除目录链接，仅通过 fd 持有，进程被强制结束也不遗留大快照。先完整校验快照，再建立上传事务。保存支持的元数据字段并规范化数值表示，避免异常扩展/数值文本膨胀目标清单。第二次顺序读取同一快照，将源 Huffman/LZ77 内容解码为原文，复用 `UploadSourceSink` 逐块上传，Server 按目标策略重新编码。两次全包摘要必须相同，提交前再次检查中断。

新 `begin_import` 仅在认证后使用，保留历史来源作为描述，不重新读取该来源或把它当作正在扫描的目录。它允许归档中的历史 socket 节点；普通备份仍拒绝新 socket 上传。Server 继续验证条目范围、目录顺序、链接关系、长度和摘要，使用已有 staging、持久化及原子版本发布流程。导入不能覆盖已有版本，也不创建或更改任务配置。

截断、损坏、非法路径/属性、组外硬链接、未知格式/标志、计数不符和多余字节均拒绝。部分属性中 UID/GID 的全 1 值属于 chown 的“不修改”哨兵，不作为可恢复身份接受。空间不足或传输中断时，不发布半成品版本；失败 staging 与普通备份一样保留诊断信息，旧版本继续可恢复。导出普通失败会清理临时文件；强制杀死导出进程可能留下隐藏临时文件，但不会出现可用的目标归档。

提交回执丢失时按同一执行 ID 查询，避免重复发布；无法确认时保留 WAITING，可从执行记录确认结果。导入上传过程中修改原归档不会改变已验证快照的内容。

## 模块与范围

- [archive.h](../include/backup/core/archive.h) / [archive.cpp](../src/core/archive.cpp)：格式、顺序读取、流式解码和校验，使用同步回调传递已解码内容。
- [VersionVerifier](../include/backup/core/version_verifier.h)：归档与普通还原共用清单、范围、目录及摘要校验。
- [archive_export.cpp](../src/agent/archive_export.cpp)、[archive_import.cpp](../src/agent/archive_import.cpp)：工作线程中的导出发布与导入事务。
- [archive-handlers.ts](../apps/backup-desktop/electron/archive-handlers.ts)：主进程文件选择和白名单调用；内容字节不进入 Renderer。

只有一个归档格式，使用具体读写类、普通函数和同步回调；继续复用压缩算法、筛选及接收者虚接口。大文件内容有界处理，目录校验所需状态随条目数量增长。当前为顺序归档，无独立随机访问索引、增量归档或断点续传。

本轮交付未加密 BSAR1；FR-15 仓库及归档加密仍属后续目标，不接受未知加密标志。格式编码不依赖本机结构体布局，但特殊节点与属性恢复仍限定现有 Linux 范围，没有据此声称跨平台还原、ACL/xattr 或物理掉电已验收。命令与实际结果见[测试报告](test-report.md)。
