# 仓库与归档加密

用新版 Server 指向一个新的空仓库，启动桌面软件，在「备份目标」中新增该服务的地址和端口并保存。点目标行上的「启用加密」，输入并确认密码。成功后仓库已解锁，可以按原流程备份、还原、导出。加密策略随仓库保存，已有明文备份历史的仓库需要迁移到新仓库，可以通过归档导入完成。
在项目目录运行下面的命令可另起服务。请使用尚未占用的路径和端口。

```bash
BACKUP_DATA_DIR="$PWD/../BackupSystem-encrypted" ./scripts/run-server.sh --port 9001
```


「锁定」释放 Agent 中的仓库密钥。关闭窗口时独立 Agent 继续运行，已解锁的实时任务可以继续备份。重启 Agent 后，受保护任务进入「等待解锁仓库」，重新输入密码后补扫变化。仓库密码丢失后无法还原。升级时需要同时重启 Server 和常驻 Agent。

加密仓库导出的 `.bsar` 使用原仓库密码。即使原仓库和服务不可用，也可以在「备份版本」点「导入加密归档」，输入归档密码并选择文件。新版本使用目标仓库自己的压缩和加密策略。导入到未加密目标时，需明确勾选允许保存未加密内容。已有未加密 BSAR1 可通过「导入归档」导入。

## 课件对应及实现

两份本地课件展示 AES、密码派生、版本化加密头、EVP 分块读写和算法接口。实现采用 OpenSSL 3 的 [EVP](https://docs.openssl.org/3.0/man3/EVP_EncryptInit/) AES-256-GCM，在解密时验证每块认证标签。每个仓库使用 16 字节随机盐，[scrypt](https://docs.openssl.org/3.0/man7/EVP_KDF-SCRYPT/) 固定参数 N=2¹⁷、r=8、p=1 和有界内存。派生密钥仅用于封装独立的随机 256 位仓库密钥。密码不进入服务器请求、任务配置或执行记录。Agent 仅缓存已解锁的仓库密钥，释放时清除密钥字节。

| 模块 | 职责 |
| --- | --- |
| [IEncryptionAlgorithm](../include/backup/core/encryption.h) | 声明 seal/open 虚接口，AES-GCM 实现隔离 OpenSSL 上下文和标签验证 |
| [VaultKeys](../src/agent/vault.cpp) | 创建和解锁仓库、关联固定仓库身份、管理内存密钥 |
| [SealedUpload](../src/agent/sealed_upload.cpp) / [SealedDownload](../src/agent/sealed_download.cpp) | Agent 将现有文件和清单流程转换为密文逻辑区段，解封后交回原有还原和导出流程 |
| [Repository 密文存储](../src/server/sealed_repository.cpp) | 校验偏移、密文长度和储存摘要，原子发布版本。Server 不保有仓库密钥 |
| [加密归档设备](../src/agent/sealed_archive.cpp) | 通过 QIODevice 的虚接口封装 BSAR1 读写，流式认证密文，复用现有归档格式和校验器 |

仓库公开头存有格式、仓库 ID、盐和封装密钥。每版用独立子密钥，文件先分块压缩再加密。认证数据绑定仓库、版本和密文位置。来源、清单、规则、属性、内容、哈希和警告进入密文，公开存储只包含版本/任务 ID、时间、密文长度和必要的格式字段。上传先写暂存目录，通过 Agent 清单校验及 Server 密文摘要校验后发布，断线时沿用原版本确认逻辑。还原先验证清单，每个文件校验认证标签及原文完整性后才发布，失败后已有成功文件会在执行记录中显示。

加密归档外层为 BSAE v1，封装头携带密码派生材料、封装密钥和随机归档 ID。每块绑定归档头摘要、顺序及长度，认证终帧后还要检查 EOF。成功解密的流交给 BSAR1 校验器。导入两遍读取私有快照，第一次验证完整性，第二次才上传。导出在同目录临时文件中验证后发布。这使归档验证与仓库密钥解锁独立于原服务。

当前实现采用课程提供的 OpenSSL 库，密码算法由库实现。Agent 本机的任务配置和执行记录仍含源路径等操作信息。仓库加密保护 Server 保存的备份及导出的归档。远端 TLS、密码轮换和开机自启不包含在本次功能内。
