# Linux 元数据保存与恢复

2026-11-17 补齐 FR-12：对普通文件、目录、软链接、硬链接和 FIFO 保存 UID、GID、rwx 权限及纳秒级 mtime，并在当前权限允许时恢复。软链接不承诺 Linux 不支持的权限位恢复；ACL、扩展属性、atime、ctime、特殊权限位和设备内容不属于本轮范围。

## 恢复顺序

1. 校验完整清单及根目录元数据；非法字段、不完整元数据和冲突的硬链接元数据在创建还原目标前失败。
2. 普通文件先写临时文件并核对内容摘要，再刷新 Qt 写缓冲；之后恢复属主/属组、权限和修改时间，完成同步后无覆盖发布。避免刷新缓冲时覆盖已设置的 mtime。
3. 硬链接只引用本次已验证的代表文件，共享其元数据。旧清单中别名没有元数据时沿用代表文件信息；如果明确记录了不同元数据则拒绝恢复。
4. 软链接和 FIFO 按不跟随链接的系统调用恢复元数据；不读取链接目标或管道内容。
5. 先验证全部硬链接关系，再按从子目录到父目录的顺序恢复目录元数据，最后恢复根目录。目录遍历权限收紧后不再按路径检查其后代。

复用的校验器 `validateMetadata()` 用于清单、Server 上传根元数据及 Agent 还原根元数据，不引入新版本格式。恢复使用 fd 与不跟随软链接的 parent/leaf 两个普通函数，分别顺序调用系统 API，共用字段解析和完整警告汇总；不再保留额外的虚目标接口。见[接口与职责说明](architecture-refactoring.md)。

## 权限不足与历史记录

恢复不自动提权。属主、权限或时间设置失败时，继续完成内容还原，在警告中记录路径、字段（`owner/group`、`permissions`、`modification time`）及系统原因。根目录失败同样计入；超过 100 条时保存完整明细，使用现有执行记录接口分页查看，不截断为第一页。已有源版本警告与元数据警告同时保留。

还原结果保留 `metadata_warning_count`；界面明确显示“内容已恢复，元数据未完全恢复”。重新打开执行记录仍可查询相同计数和明细。发生内容/校验/持久化错误时，仍按既有失败与部分写入语义处理。

旧版本未记录的元数据无法补回，保留原有兼容恢复行为。新备份依旧使用未压缩格式 4 或压缩格式 5，不重写历史版本。

## 验证

`backup-metadata` 比较根目录、普通文件、空文件、硬链接、只读目录、软链接和 FIFO 的权限/UID/GID/mtime，覆盖不压缩、Huffman、LZ77、纳秒和纪元前时间、受限目录、旧格式兼容、损坏元数据拒绝。仅测试库注入元数据系统调用失败，核对超过一页的完整警告、根目录计数及重启持久化；生产接口没有故障开关。

`backup-metadata-owners` 在私有用户/挂载命名空间内只读绑定不同属主的真实文件，验证无法恢复不可映射 UID/GID 时仍恢复内容和其余元数据，明确报告失败字段。它不修改宿主文件属主，不提供宿主 root 权限。

桌面回归包含真实属主恢复失败、提示、警告与写入明细同时展开，以及重新加载后的查询。命令与实际结果见 [测试报告](test-report.md)；不宣称完成物理掉电、任意文件系统或百万条目验收。
