# 实时备份（Linux）

在“备份任务”卡片勾选 **实时备份**。第一次开启会备份当前内容；之后新增、修改、删除和重命名目录内的文件会触发新版本。设置按任务保存，默认关闭。关闭开关停止监听与后续自动调度，已经开始的备份仍完成。

关闭整个桌面软件后，Agent 仍在后台运行，Server 也需要保持运行。再次打开软件会连接同一 Agent，可以查看后台产生的版本与执行记录。首次更新到此实现时先关闭旧版桌面软件，再运行 `./scripts/run-agent.sh`。机器重启后首次启动软件会恢复 Agent 并对已开启的任务重新备份；本轮没有安装系统开机自启服务。

## 状态和异常

| 卡片状态 | 含义 |
| --- | --- |
| 监控中 | 当前变化已处理，正在等待新变化 |
| 等待备份 | 变化正在合并或等待其他操作完成 |
| 正在备份 | 复用完整备份流程，正在生成新版本 |
| 待连接 | 目标不可达或连接断开，保留待处理变化并自动重试 |
| 待认证 | 远端会话过期或未登录，重新登录后补扫 |
| 待解锁 | 加密仓库需输入密码，解锁后补扫 |
| 等待重试 | 来源、存储或持久化失败，错误仍保留，并逐步延长重试间隔 |
| 等待确认提交结果 | 无法确认服务器是否已提交；通过执行记录确认原操作，确认后继续处理积累的变化 |
| 监听受限，定期核对 | inotify 资源或目录权限不足，使用属性核对补偿并显示原因 |

来源根目录或明确选定的来源本身被移走/删除时保留错误并等待其恢复，不把不可访问的来源误报为成功的空备份。选定文件夹内部文件的删除、重命名会反映到下一版本。筛选、压缩、元数据和特殊文件规则与手动备份相同。排除范围的通知可能唤醒调度，但不会把被排除的数据写入版本。

## 实现

- [ControlService](../src/agent/control_service.cpp) 提供 Unix socket 控制服务。GUI 的 `backup-agent --connect` 子进程只做代理；首次连接会分离启动 `--daemon`。GUI 退出只结束代理。原有标准输入模式保留给命令行和集成测试。
- socket 位于 `/tmp/backup-agent-<uid>-<状态目录摘要>/control.sock`，目录必须属于当前用户且权限为 0700，socket 限当前用户访问。State 排他锁保证同一状态目录只有一个服务；仅获得锁的实例清理旧 socket。请求 ID 按连接重新映射，断连仅取消答复，不取消工作；请求与输出缓冲有大小限制。
- [Realtime](../src/agent/realtime.cpp) 使用一个监听线程处理每个启用任务，事件线程统一调度，单个已有数据工作线程执行备份。扫描属性不读取文件内容、不打开设备/FIFO、不递归软链接；目录列举固定描述符，避免目录替换后跟随链接。
- Linux inotify 覆盖目录和普通文件，父目录通知处理选定文件的原子替换以及来源重建。连续修改等待约 1.2 秒安静期，持续写入最长约 10 秒进入调度；忙碌时只保留待处理状态。按最早到期任务选择，避免第一个任务持续变化饿死其他任务。
- 事件发生后重建必要监听；每 30 秒核对路径、inode、类型、权限、属主、大小、mtime、ctime。属性没有变化不会周期性创建版本；事件队列溢出会重新核对整个范围。监控资源不足时显示降级原因，继续属性核对。
- 工作期间的新变化不会被成功回调清除，会再执行一次完整备份。失败按 4、8、16、32、60 秒重试；崩溃后恢复开启设置并重新核对。每版独立保存完整内容，未实现跨版本增量/去重。
- 不确定提交使用已有 WAITING/confirm 机制，关闭再开启监控也不能绕过确认；重启从持久化执行记录恢复此状态。
- 配置格式 8 保存 `realtime` 布尔值，旧版 Agent 明确拒绝。`config` 额外返回进程 PID、busy 和每任务实时状态；自动记录带 `trigger: realtime`。配置先持久化再调整监听。

本轮使用具体控制服务、调度对象和回调连接职责，复用已有 `ISourceSink`、`IBackupFilter`、压缩算法虚接口；没有为单一 Linux 监听实现增加空泛的虚基类。加密仓库已接入「等待解锁仓库」及解锁后补扫，见[加密说明](encryption.md)。远端任务可在会话过期或 Server 重启后重新登录并补扫。部署步骤见[远端备份说明](remote-backup.md)。

## 人工验证

1. 启动 Server 和桌面软件，给一个测试文件夹创建任务，勾选实时备份，等待卡片显示“监控中”。
2. 连续编辑文件、新建子目录、重命名或删除文件，等待新版本出现，选新版本还原到空目录并核对内容。
3. 关闭桌面软件，继续修改测试文件。数秒后重开软件，查看后台版本与执行记录，确认可以还原修改后的内容。
4. 停止测试 Server 后修改文件，卡片应显示待连接；恢复同一仓库和端口，等待自动完成。
5. 关闭实时开关后继续修改文件，应不再自动创建版本。已经开始的任务仍会完成。

实际测试及未覆盖边界见 [测试报告](test-report.md)。
